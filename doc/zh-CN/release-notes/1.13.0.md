# Chats 1.13.0 发布说明

> 发布日期：2026-08-05（相对 1.12.0.702 以来 23 次非 merge 提交）

1.13.0 主要增强了 **MCP 使用体验** 和 **模型原生联网搜索能力**。用户现在可以把常用 MCP 服务固定为聊天输入框快捷按钮，并由 MCP Server Instructions 自动补充模型上下文；“智能搜索”则扩展到 OpenAI/Azure Responses、DeepSeek Messages 和小米 MiMo 等协议与模型，同时完善搜索过程、结果引用和多轮历史的展示与还原。本版本还修复了推理内容顺序和局域网 HTTP 环境下的复制问题，并升级至 Node.js 24、MCP SDK 2.0 及新版本的前后端依赖。

## 🎯 核心功能

### 1) MCP 快捷按钮

- ⚡ **聊天输入框快捷开关**：可以把已分配的 MCP 服务显示为聊天输入框中的独立按钮，一键为当前聊天中支持工具调用的模型启用或停用该 MCP，无需反复进入聊天配置。
- 👤 **用户级快捷方式偏好**：`Show Shortcut` 保存在用户与 MCP 的分配关系上，同一个 MCP 可以由不同用户分别决定是否显示快捷按钮。
- 🧑‍💼 **分配关系统一管理**：管理员和 MCP 所有者可以调整已分配用户的快捷按钮状态；管理员新增用户分配时也可以直接指定，新用户默认继承分配者当前的快捷设置。
- 🧭 **仅在适用时显示**：没有配置快捷 MCP，或当前聊天没有支持工具调用的模型时，不会显示无效按钮。

### 2) MCP Server Instructions

- 📝 **获取服务端指令**：刷新 MCP 工具列表时会同时读取 MCP SDK 提供的 `ServerInstructions`，并自动带入 MCP 编辑界面。
- ✏️ **支持检查和编辑**：服务端指令可以在保存前人工调整，也可以为空，不要求 MCP 服务必须提供该字段。
- 🧠 **自动注入模型上下文**：聊天调用时，当前启用 MCP 的 Server Instructions 会按 MCP 名称整理并追加到系统消息中，同时保留原有系统提示词和代码执行提示词。
- 🔄 **MCP SDK 2.0**：升级 `ModelContextProtocol.Core` 至 2.0.0，并完善 MCP 客户端与 HTTP transport 的异步释放和错误处理。

## 🌐 智能搜索与协议能力

### 1) OpenAI / Azure Responses 联网搜索

- 🔍 **原生 `web_search` 工具**：OpenAI 和 Azure AI Foundry 的 Responses API 模型可以通过聊天输入框中的“智能搜索”按钮启用托管联网搜索。
- 🔗 **搜索过程与引用展示**：解析 `web_search_call`、搜索状态和 `url_citation`，把搜索动作与来源结果以统一工具调用样式展示，并保留到聊天历史中。
- 🧩 **复杂响应兼容**：支持从嵌套对象或数组字段中提取引用，修复多次搜索交错返回时调用和结果配对错误，以及刷新历史消息后搜索展示丢失的问题。
- 🔌 **Endpoint 兼容增强**：Responses 和 Models 请求会识别已经包含 `/v1` 或目标资源路径的 endpoint，避免重复拼接路径；同步完善流式、后台异步响应及取消请求的处理。
- 🚦 **错误分类更准确**：Responses API 失败时会区分内容安全拦截与普通上游错误，并优先返回上游提供的具体错误消息。

### 2) DeepSeek 与 MiMo 联网搜索

- 🐋 **DeepSeek Messages 托管搜索**：DeepSeek 的 Anthropic Messages 兼容接口支持 `web_search_20250305` 服务端工具，能够流式处理搜索调用、结果和引用。
- 🧾 **历史消息可继续对话**：DeepSeek 搜索的原始 `server_tool_use` / `web_search_tool_result` 会在内部保留，后续请求可按上游协议还原；前端展示会转换为统一的搜索工具卡片，并移除不需要暴露的加密内容。
- 📱 **小米 MiMo 搜索支持**：MiMo Chat Completions 会按聊天配置发送 `web_search` 工具，并从响应 annotations 中整理标题、URL、摘要、站点和发布时间等搜索结果。
- 🎛️ **统一智能搜索开关**：当聊天包含支持联网搜索的模型时，输入框显示“智能搜索”按钮，并同步更新所有具备该能力的聊天分支。

## 🛠️ 协议与稳定性改进

- 🧠 **推理内容顺序修复**：Chat Completions 同一增量或同一响应中同时返回推理和正文时，始终先保存和展示推理内容，再展示最终回答，避免正文之后追加更早的推理片段。
- 🔀 **推理字段兼容**：同时识别上游返回的 `reasoning_content` 和 `reasoning`，并整理 MiniMax、MiMo 等模型的推理内容回传与历史序列化逻辑。
- 🌊 **Responses 方言兼容**：兼容 DeepSeek、MiMo 等服务在 Responses 流中使用的直接 `reasoning_text`、终止事件、usage 和输出结构；流在没有终止事件时会明确报告上游异常，避免把不完整响应当作成功。
- 📚 **历史内容顺序稳定**：从数据库恢复 step 内容时按内容 ID 排序，降低工具调用、推理和正文在后续请求中顺序错乱的风险。
- 📋 **局域网 HTTP 复制修复**：统一封装复制逻辑；当非安全上下文中无法使用 Clipboard API 时，自动使用兼容方案。代码块、消息、Mermaid、Request Trace、会话命令和配置页面等复制入口均已接入。
- 🌍 **资源域名修复**：更新下载地址、构建文档和模型图标等资源域名，解决原 `sdcb.pub` 域名失效造成的访问问题。

## ⚙️ 工程与运维更新

- ⬆️ 前端构建环境升级至 Node.js 24.18.0 和 npm 12.0.1，并声明 Node.js 24 / npm 12 最低版本要求。
- 📦 升级 Next.js、React、Entity Framework Core、Azure/AWS SDK、Playwright、Swashbuckle、MiniExcel 等前后端依赖，并完成 npm 安全审计修复。
- 🗃️ SQLite 运行时新增显式原生库依赖，1.13.0 同时提供 SQL Server 和 SQLite 数据库迁移脚本。
- ☁️ Azure Blob 到 MinIO 的文件迁移工具新增默认 dry-run、源文件探测、MinIO 抽样检查、并行迁移、数量限制、缺失文件跳过、源文件可选删除和进度统计等选项。
- 🚀 发布流水线增加前端和后端源码包的 R2 `release/latest` 上传，并更新自托管部署 runner 标签。

## 🐛 修复汇总

- 修复 Responses 联网搜索引用位于数组字段时无法识别的问题。
- 修复 Responses 多个搜索调用交错返回时引用绑定到错误搜索的问题。
- 修复刷新或重新加载消息后，托管搜索被显示成普通工具调用或丢失搜索结果样式的问题。
- 修复 Chat Completions 推理片段可能出现在正文之后的问题。
- 修复局域网 HTTP 地址访问 Chats 时多个复制按钮无响应的问题。
- 改进 MCP 工具获取时的超时、JSON、IO 和无效响应错误处理。
- 修复动态组件缓存可能在 React 渲染期间读取旧组件的问题，并调整前端 ESLint 配置以适配升级后的规则结构。

## ⬆️ 升级提示

- SQL Server 部署运行：`src/scripts/db-migration/1.13/1.13.0.sql`
- SQLite 部署运行：`src/scripts/db-migration/1.13/1.13.0-sqlite.sql`
- 本次数据库迁移包含：
  - 为 `McpServer` 新增可空字段 `ServerInstructions`，用于保存 MCP 服务端指令。
  - 为 `UserMcp` 新增非空字段 `ShowShortcut`，存量用户默认值为 `false`，升级后不会自动在聊天输入框显示已有 MCP。
- 如果自行构建前端，请将环境升级至 Node.js 24 和 npm 12；仓库 Volta 配置使用 Node.js 24.18.0、npm 12.0.1。
- `fetch-tools` 接口响应由工具数组调整为包含 `tools` 和 `serverInstructions` 的对象；如果有外部管理工具直接调用该接口，需要同步适配新的响应结构。
