# Chats 1.16.0

本版本优化了大型分支聊天的加载方式，增加了模型与 Model Key 的物理删除能力，并增强了聊天消息编辑与图片输入体验。

## 助手回答一键下载长图

- 在助手回答操作栏新增下载图片按钮，支持将当前已经渲染完成的回答直接导出为单张 PNG 长图，无需打开打印窗口或重新解析 Markdown。
- 导出内容复用当前页面的 Markdown、KaTeX 公式、Mermaid 流程图、代码高亮、表格、图片和工具结果渲染结果，避免导出内容与页面显示不一致。
- 图片主题跟随当前界面主题，深色和浅色模式均保持原有背景、文字、代码块和表格样式。
- 使用 SnapDOM 按需异步加载，避免增加首屏主 bundle；导出过程中按钮显示加载状态，生成并触发下载完成后恢复。
- 对超大回答增加单张图片尺寸保护，避免浏览器生成截断或空白图片。

## 加载图标动画统一

- 统一 `IconLoader` 的旋转实现：组件内部使用稳定的 `inline-flex` 包裹层承载旋转动画，避免 SVG 直接应用 `animate-spin` 在不同场景下表现不一致。
- 聊天输入、文件上传、会话管理、侧边栏、消息操作及管理员界面的加载状态均复用统一的自动旋转 `IconLoader`，调用方不再重复声明旋转类。

## 会话列表标题显示修复

- 修复会话列表标题中 `g`、`j`、`p`、`q`、`y` 等带下伸部分的字母底部被裁切的问题。移除过小的 `leading-4` 行高限制，使标题文字在单行省略显示时完整可见。

## 聊天消息按当前视图懒加载

- 使用新的 `GET /api/chats/{chatId}/messages` 消息视图接口替代原有全量消息接口。首次加载聊天时只返回当前选中叶节点对应的可见消息路径，而不是完整返回整棵聊天树。
- 对当前路径上的消息保留左右切换所需的轻量分支元数据，例如兄弟消息 ID、分支数量和当前选中位置；未显示分支不在首屏返回完整的 Step/Content 数据。
- 用户切换到其它分支时，通过子树接口异步加载目标 sibling 以及该子树中默认可见的后代路径，逐步补充前端本地消息缓存，降低聊天树较大时的首屏响应体积和解析开销。

## 模型与 Model Key 支持物理删除

- 管理员删除模型时直接物理删除活动 `Model` 记录，不再因为模型被聊天或预设引用而降级为禁用模型。
- `ChatConfig.ModelId` 已改为可空，并使用 `ON DELETE SET NULL` 保留原有的 `ChatConfig`、`ChatSpan` 和 `ChatPresetSpan`。模型被删除后，相关聊天配置会显示模型不可用，但仍可打开配置弹窗并改选其它可用模型；在重新配置前不会继续生成消息。
- `UserModel`、`UserApiModel` 和 `UserApiCache` 等活动关联在删除模型时级联清理。历史聊天和用量依赖的 `ModelSnapshot`、`ModelKeySnapshot`、`ChatConfigSnapshot` 等不可变快照继续保留，确保历史内容仍可读取。
- Model Key 在没有启用模型时显示删除入口并允许物理删除；密钥下的模型全部删除或禁用后即可删除密钥，禁用模型及其活动关联会一并清理。历史聊天和用量依赖的快照与交易记录继续保留；如果仍存在启用模型，后端会拒绝删除，避免误删正在使用的配置。
- 现有数据库需要按数据库类型执行 `src/scripts/db-migration/1.16/1.16.0.sql`（SQL Server）或 `src/scripts/db-migration/1.16/1.16.0-sqlite.sql`（SQLite），以应用可空列和新的外键删除策略。

## 聊天消息编辑与图片输入增强

- **用户消息支持完整编辑**：用户消息编辑改用完整的 `MessageContentEditor`，可同时修改文本、保留已有图片、添加或删除图片，并支持设备上传、远程文件选择、剪贴板粘贴和拖拽上传。
- **后端支持富内容编辑**：新增用户消息原地编辑及编辑后另存为新消息的接口，文本响应编辑接口继续保留并收敛为响应消息专用；公共编辑校验、Turn 构建和用量计算逻辑已统一抽取。
- **输入区域事件隔离**：图片粘贴上传仅在当前输入区域生效，用户消息编辑器和底部 `ChatInput` 不再互相抢占粘贴事件；`Alt+S` 发送快捷键也按当前输入区域执行。
- **编辑位置保持稳定**：修复编辑非末尾多分支响应时误触发 leaf 切换并滚动到底部的问题；编辑器状态不会再被上层消息重渲染覆盖，上传完成的图片和正在编辑的文本可以稳定保留。
- **发送控件统一**：用户消息编辑器复用与底部 `ChatInput` 一致的发送按钮，并针对编辑器布局使用更紧凑的高度。

## 🐛 问题修复

- **思考内容展示修复**：修复 Responses API 在网页搜索等工具密集场景中返回仅包含推理签名、但没有可展示思考文本的 reasoning item 时，界面生成多个空白“思考中”区块，并为它们重复显示同一个 Step 思考耗时的问题。真实思考内容仍会在收到流式片段后立即显示；进入正文、工具调用等后续阶段或流结束时，空白思考会被自动清理，非空思考则正常结束。刷新或重新打开聊天时，历史消息接口也会隐藏空白思考，但数据库中的推理签名仍会保留并继续用于后续模型上下文。

## 愿景

以下方向用于记录后续演进设想，不属于本版本已经交付的能力。

### Turn 级别的 LeafId

- 当前聊天只有一个聊天级 `LeafTurnId`。懒加载切换到不包含该 leaf 的 sibling 子树时，当前实现先按目标子树中最深且最新的 leaf 选择默认可见路径。
- 后续可为每个 turn 或分支增加独立的 `LeafTurnId`，使用户返回曾经浏览过的分支时可以恢复该分支上一次选中的后代，而不是重新按最新 leaf 推导。
- 这项持久化模型重构需要重新设计 turn 级 leaf 的更新、删除、复制、分享和数据库迁移方案。

### 更细粒度的内容按需加载

- 思考内容等非当前界面必需的消息内容可进一步改为按需加载，避免历史分支数据在首次打开聊天时被全部传输。
