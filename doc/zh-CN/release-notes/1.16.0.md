# Chats 1.16.0 规划说明

1.16.0 目前处于规划阶段，以下内容是拟进行的重构方向，尚未开发，也不代表当前版本已经提供相关能力。

## 聊天消息按当前视图懒加载

- 重构 `GET /api/messages/{chatId}` 的返回策略。首次加载聊天时只返回当前选中叶节点对应的可见消息路径，而不是完整返回整棵聊天树。
- 对当前路径上的消息保留左右切换所需的轻量分支元数据，例如兄弟消息 ID、分支数量和当前选中位置；未显示分支不在首屏返回完整的 Step/Content 数据。
- 用户切换到其它分支时，再通过异步请求按需加载对应分支，逐步补充前端本地消息缓存，降低聊天树较大时的首屏响应体积和解析开销。
- 思考内容等非当前界面必需的消息内容也将评估按需加载，避免历史分支数据在首次打开聊天时被全部传输。

## 模型与模型提供商支持物理删除

- 在管理界面为模型和模型提供商增加删除入口，目标是支持物理删除，而不只是通过禁用状态隐藏。
- 重点处理模型、模型提供商、`ChatConfig`、`ChatPresetSpan`、`ChatSpan` 之间的非空外键关系，重新定义删除时的解绑、级联或阻止策略。
- 区分当前可编辑配置与历史快照：活动模型及其配置可以在满足引用约束时删除，历史聊天依赖的 `ModelSnapshot`、`ChatConfigSnapshot` 等不可变历史数据继续保留，确保历史会话仍可读取和复现。
- 删除流程、已有预设/聊天引用、模型 Key、用量记录及其它关联数据的具体迁移方案和兼容行为，待后续实现阶段确定。

## 状态说明

- 以上两项均为 1.16.0 的规划方向，当前尚未实现。
- 正式实现后将补充 API、数据库迁移、前端交互和升级说明。
