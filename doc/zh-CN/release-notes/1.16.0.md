# Chats 1.16.0

本版本优化了大型分支聊天的加载方式，并增加了模型与 Model Key 的物理删除能力。

## 聊天消息按当前视图懒加载

- 使用新的 `GET /api/chats/{chatId}/messages` 消息视图接口替代原有全量消息接口。首次加载聊天时只返回当前选中叶节点对应的可见消息路径，而不是完整返回整棵聊天树。
- 对当前路径上的消息保留左右切换所需的轻量分支元数据，例如兄弟消息 ID、分支数量和当前选中位置；未显示分支不在首屏返回完整的 Step/Content 数据。
- 用户切换到其它分支时，通过子树接口异步加载目标 sibling 以及该子树中默认可见的后代路径，逐步补充前端本地消息缓存，降低聊天树较大时的首屏响应体积和解析开销。

## 模型与 Model Key 支持物理删除

- 管理员删除模型时直接物理删除活动 `Model` 记录，不再因为模型被聊天或预设引用而降级为禁用模型。
- `ChatConfig.ModelId` 已改为可空，并使用 `ON DELETE SET NULL` 保留原有的 `ChatConfig`、`ChatSpan` 和 `ChatPresetSpan`。模型被删除后，相关聊天配置会显示模型不可用，但仍可打开配置弹窗并改选其它可用模型；在重新配置前不会继续生成消息。
- `UserModel`、`UserApiModel` 和 `UserApiCache` 等活动关联在删除模型时级联清理。历史聊天和用量依赖的 `ModelSnapshot`、`ModelKeySnapshot`、`ChatConfigSnapshot` 等不可变快照继续保留，确保历史内容仍可读取。
- Model Key 仅在不包含任何活动模型时显示删除入口并允许物理删除；如果绕过前端直接请求删除非空 Key，后端仍会拒绝，避免连带误删模型。
- 现有数据库需要按数据库类型执行 `src/scripts/db-migration/1.16/1.16.0.sql`（SQL Server）或 `src/scripts/db-migration/1.16/1.16.0-sqlite.sql`（SQLite），以应用可空列和新的外键删除策略。

## 愿景

以下方向用于记录后续演进设想，不属于本版本已经交付的能力。

### Turn 级别的 LeafId

- 当前聊天只有一个聊天级 `LeafTurnId`。懒加载切换到不包含该 leaf 的 sibling 子树时，当前实现先按目标子树中最深且最新的 leaf 选择默认可见路径。
- 后续可为每个 turn 或分支增加独立的 `LeafTurnId`，使用户返回曾经浏览过的分支时可以恢复该分支上一次选中的后代，而不是重新按最新 leaf 推导。
- 这项持久化模型重构需要重新设计 turn 级 leaf 的更新、删除、复制、分享和数据库迁移方案。

### 更细粒度的内容按需加载

- 思考内容等非当前界面必需的消息内容可进一步改为按需加载，避免历史分支数据在首次打开聊天时被全部传输。
