# Chats 1.15.0 发布说明

Chats 1.15.0 开始清理 1.14.0 中保留的兼容行为，并将 Prompt 明确收敛为可命名、可搜索的纯文本快捷输入。

## MCP Server 与工具元数据

- MCP Server 将协议名称 `Name` 与用户显示名称 `DisplayName` 分离。`Name` 必须符合 `^[A-Za-z0-9_-]{1,50}$`，用于生成模型侧的稳定工具名 `mcp__<server.Name>__<toolName>`；面向模型的说明文本在有显示名称时使用 `DisplayName (Name)`，管理界面和快捷选择器按场景显示显示名称或协议名称。
- 工具管理页现在支持编辑 `Title`、`Description`、`Parameters`，并以紧凑开关展示当前参与执行策略的 `ReadOnly` 与 `Idempotent`。重新获取工具会继续覆盖整张工具表，并从 MCP annotations 同步四个 hint；未声明的值按 `false` 保存，`Destructive/OpenWorld` 本期仅作为后端元数据保留。
- 工具调用记录保存展示名称快照，历史记录和无标题工具回退显示协议名称；SSE、实时工具卡和历史消息都保留原始协议名称用于模型交互、复制和识别。

## MCP 调用并行与重试

- 连续的 `ReadOnly=true` MCP 调用会组成并行批次，单批最多并发 4 个；非只读工具、Code Interpreter 和未知工具仍作为串行屏障，批次之间严格按模型调用顺序执行。
- `Idempotent=true` 的失败调用最多重试 2 次（总计 3 次尝试），使用约 1 秒、2 秒退避和少量抖动。同一模型输出 step 内按 MCP Server 懒创建并复用 Client；工具错误重试继续复用健康 Client，连接或 Session 故障会淘汰并按需重建，且不会额外调用 `ListToolsAsync`。
- `Destructive` 与 `OpenWorld` 本版本只作为可编辑元数据保存和同步，暂不改变确认流程或执行策略。工具最终失败仍会作为失败结果交给模型，不会中止整个聊天。

## MCP 配置校验

- 同一聊天配置不能同时启用名称相同（不区分大小写）的 MCP Server，即使 Server 属于不同 Owner；快捷选择器、预设、快捷按钮和服务端保存都会进行校验。
- 修改已被聊天或预设使用的 Server `Name` 时，如果会制造同配置内的重复名称，保存会被拒绝。

## Prompt 行为收敛

- Prompt 表、个人/系统/默认 Prompt、管理界面、CRUD API、温度设置及 `/xxx` 快捷选择均继续保留。
- 选中 Prompt 后，其内容会原样插入聊天输入框或 System Prompt。
- `{{CURRENT_DATE}}`、`{{CURRENT_TIME}}`、`{{MODEL_NAME}}` 不再自动替换。
- `{{name}}` 等自定义占位文本不再触发变量填写弹窗，也不会执行替换。
- 已有 Prompt 中的所有 `{{...}}` 内容无需迁移，会继续作为普通文本保存和发送。

## 重试配置收敛

- 删除兼容配置项 `Chat:Retry429Times`，旧配置在 1.15 中会被 .NET 配置系统静默忽略。
- 部署配置统一使用 `Chat:MaxTransientRetries`；默认值为 `5`，设置为 `0` 可关闭重试。
- 重试仍仅发生在首段输出之前，覆盖 408、429、500、502、503、504 及网络/内部超时等瞬态错误。

## MCP 用户分配体验

- MCP 用户分配窗口的已分配用户区域改为“用户、请求头、快捷方式、操作”四列表格，以更紧凑的布局同时展示更多用户。长用户名保持单行并以省略号截断，悬停时仍可查看完整内容。
- 自定义请求头编辑框收窄为单行高度，但继续支持输入、滚动、校验和保存多行 JSON；快捷方式列同步缩窄，为请求头释放更多横向空间。
- 从右侧移除用户后，该用户会立即出现在左侧可用用户列表中，不再受尚未更新的数据库查询结果影响；保存前重新分配该用户时，会恢复其尚未保存的请求头和快捷方式设置。

## 聊天工具调用体验

- `ToolCallBlock` 不再根据后续消息或工具的显示顺序抢占展开状态，多个并行工具可以各自独立展示，不会因新的 tool call 出现而提前收起。
- 工具从调用参数流式生成开始，到执行 progress 输出期间始终保持展开；收到完成信号后保留结果 1 秒再自动收起。GPT Responses 网页搜索会在 `web_search_call` 完成时及时收起，后续 citations/result 只更新卡片内容，不会重新展开。
- 自动开合支持 `Chatting`、`Reasoning` 和 `Pending` 实时状态，快速且没有 progress 的工具也会短暂展示最终结果；历史工具默认收起，用户手动展开或收起后不再被自动逻辑覆盖。

## 🐛 问题修复

- **Responses 推理签名回传修复**：修复 OpenAI / Azure AI Foundry Responses API 在联网搜索等工具密集场景中连续返回多个 reasoning output item 时，完整 `encrypted_content` 被误当作普通思考文本片段拼接，导致后续请求返回 `invalid_encrypted_content`（密文无法验证）的问题。已完成的 reasoning signature 现在保持为独立 item，同一 item 的流式思考文本仍会与其最终 signature 正常合并；重建历史请求时也会保留 reasoning、web search、function call 与 assistant message 的原始顺序。
- **GPT 网页工具折叠修复**：将 hosted web search 的“执行完成”与“展示结果就绪”分离，`search`、`open_page` 和 `find_in_page` 不再因等待正文 citations 而在整段流式回答期间保持展开。
- **MCP 预设应用幂等性修复**：修复反复应用同一个 MCP 预设时向 `ChatConfigMcp` 持续插入重复关联，以及应用空 MCP 预设后界面虽已清空、数据库旧关联却未删除的问题。应用预设现在会完整加载并同步 MCP 关联，保留自定义请求头，同时收敛当前聊天配置中的历史重复项；模型请求组装也会按 MCP Server 去重，避免已有脏数据将 Server Instructions 和工具定义反复注入上下文。本项修复不需要数据库迁移。
- **Markdown 数学公式解析修复**：关闭单美元数学语法，避免金额、URL、Shell 变量等内容被误识别为公式并被 KaTeX 跨段吞掉；`$$...$$` 继续用于数学公式，同时兼容模型常用的 `\(...\)` 和 `\[...\]` 分隔符。
- **LaTeX 兼容转换收敛**：在统一的 Markdown 渲染入口中规范化公式分隔符，不再修改原始消息；转换过程会跳过行内代码和 fenced code block，并保留尚未闭合的流式内容。修复带尾随文本的代码围栏被错误识别为关闭行、进而改写代码内容的问题。
- **流式 Markdown 修复**：将 `▍` 流式光标移出 Markdown/KaTeX 源文本，并在 rehype 阶段插入最后一个可显示节点、置于尾随换行之前，避免公式生成过程中的 Unicode 字符警告及光标掉到下一行。
- **Markdown 布局修复**：改善正文后紧接主标题时顶部间距过小的问题。
- **用户管理移动端修复**：将修改密码从用户编辑窗口中拆分为独立的安全操作，缩短编辑表单；用户弹窗现在会限制在手机视口内滚动，并保持底部保存按钮始终可见。

## 依赖与安全维护

- .NET 与 Entity Framework Core 相关依赖由 `10.0.9` 升级至 `10.0.11`，Npgsql Entity Framework Core Provider 由 `10.0.2` 升级至 `10.0.3`。
- Microsoft Playwright 由 `1.61.0` 升级至 `1.62.0`，AWS SDK for S3 由 `4.0.100.3` 升级至 `4.0.102.1`，Microsoft.NET.Test.Sdk 由 `18.7.0` 升级至 `18.9.0`。
- 移除对 `SQLitePCLRaw.lib.e_sqlite3` 的冗余显式引用，改由 Entity Framework Core 的 SQLite bundle 统一传递管理；其携带的原生 SQLite 引擎仍为 `3.53.3`。
- 完成包含传递依赖的 NuGet 漏洞检查，本次升级后未发现已知漏洞依赖。

## 升级说明

- 后端项目版本已进入 `1.15.0`。
- 升级后新产生的 Responses reasoning signature 会按原始 item 边界保存；历史对话中已经被旧版本拼接损坏的密文无法自动恢复，如仍遇到 `invalid_encrypted_content`，请从受影响轮次之前重试或新建对话。
- 请将环境变量 `Chat__Retry429Times` 改为 `Chat__MaxTransientRetries`，或将命令行参数改为 `--Chat:MaxTransientRetries`。
- SQL Server 部署先执行 `src/scripts/db-migration/1.15/1.15.0.sql`；SQLite 部署执行对应的 `1.15.0-sqlite.sql`。迁移会将历史 MCP `Label` 作为可空 `DisplayName` 保留，并用 `<McpServer.Id>` 回填协议 `Name`；四个工具 hint 的历史值统一为 `false`。
- 数据库迁移完成后再发布匹配的后端和前端；1.15 不兼容旧 MCP `label` API 字段。
