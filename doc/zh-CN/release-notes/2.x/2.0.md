# Chats 2.0

发布日期：待定

Chats 2.0 的主线是把一次对话从「一个 HTTP 请求」升级为「可持久、可交互、可发布的 Agent 运行」，对应愿景 [#155](https://github.com/sdcb/chats/issues/155)。

## 永久容器、卷与配额（#149）

- Docker 卷真实创建/删除；永久容器在工作目录挂载内部卷，并支持挂载用户独立卷（可只读）。
- 新增容器端口映射：每个运行节点配置宿主端口池（`PortRangeStart`/`PortRangeEnd`）与对外地址（`PublicHost`）；卷挂载或端口映射变化时会重建容器。
- 管理员不受用户容器配额限制（仍受节点资源上限约束）；配额新增 `MaxPortMappings`、`MaxPublishedSites`。
- 聊天输入区可选择向当前会话开放哪些永久容器。
- 禁用用户时停止其容器；回收容器时同时释放端口映射与内部卷。

## 可续传的对话运行（#150）

- 每次生成都是一个持久化的 Run（`ChatRun`/`ChatRunEvent`）：客户端断开、刷新后 Run 继续执行，事件带 SSE `id:` 序号，可通过 `GET /api/chat-runs/{runId}/events?after=N` 续传。
- 打开会话时自动接回正在运行的 Run；停止按 runId 写入数据库，多实例部署下同样生效。
- 心跳超时（60 秒）的孤儿 Run 自动标记为失败；已结束 Run 的事件按 `ChatRun:EventRetentionMinutes`（默认 60 分钟）清理。
- SSE 在长时间无输出的工具调用期间发送 keep-alive 注释，避免被代理断开。

## 计划模式与 ask_question（#151）

- 输入区新增「计划」模式（按会话记住），模型先给出计划再执行。
- 内置 `ask_question` 工具（每次 1–3 题，支持单选/多选/文本与默认值）：提问后 Run 挂起、不占用线程，用户回答、跳过或直接发送新消息后在同一回答中继续；历史中显示为已回答卡片。

## 运行中插话（#152）

- Run 进行中输入框变为「补充」：消息排队，在下一次工具结果之后注入；若本轮已无工具调用，则注入后再推理一轮。
- 停止或运行结束时未注入的补充会被丢弃并回填到输入框；排队状态刷新后可恢复。

## 网站托管（#153）

- 把永久容器的端口发布为 `https://<子域>.<域名>`：分配端口映射 → DNS 冲突检查 → 创建 DNS 记录 → 通过 Caddy2 Admin API 添加路由；任一步失败按逆序回滚，每一步记录事件。
- DNS 提供商：Cloudflare、阿里云 DNS；只管理带 Chats 标记的记录，绝不覆盖非 Chats 创建的记录。支持 A/AAAA（网关公网 IP）或 CNAME（DDNS 主机名），可配置公网端口。
- 网关与 DNS 凭据使用 `ENCRYPTION_PASSWORD` 派生密钥 AES-GCM 加密保存，接口永不返回明文；**请务必设置并妥善保管 `ENCRYPTION_PASSWORD`，修改后需重新填写凭据**。
- 后台对账服务会重新应用路由、删除孤儿路由，并下线容器已删除的站点。
- AI 工具 `publish_website` / `list_websites` / `unpublish_website`，仅在会话可见运行中的永久容器时提供。
- 管理端 `/admin/websites`（站点、域名、网关、DNS 提供商），用户设置新增「网站」页，可一键下线。

## Provider File ID 复用（#154）

- 图片首次使用时上传到模型提供商的 Files API，之后按 `file_id` 引用，不再每次发送 base64：支持 OpenAI/Azure/DeepSeek Responses、DeepSeek Chat Completions、Anthropic/DeepSeek Messages。
- 过期预检；上游返回文件失效时标记映射失效、重新上传一次，仍失败则回退为内联；不支持的端点自动退避。
- 删除文件或模型密钥时尝试清理远端文件；配置节 `ProviderFiles`（`Enabled`、`DisabledModelKeyIds`、`DisabledProviderIds`、`OpenAIExpiresAfterSeconds` 等）。

## 升级说明

- 数据库迁移：SQL Server 运行 `src/scripts/db-migration/2.x/2.0.sql`，SQLite 运行 `src/scripts/db-migration/2.x/2.0-sqlite.sql`。
- 使用网站托管时，Caddy 需开放 Admin API，且建议以 JSON 配置 + `--resume` 方式运行，避免 reload Caddyfile 时冲掉 Chats 添加的路由；TLS 证书由 Caddy 自动管理。
- `/v1/chat/completions` 等 OpenAI 兼容接口不参与 Run 持久化、ask_question 与插话。

## 已知限制

- 发布新端口会重建容器：容器内进程会停止，只有挂载卷中的数据会保留，服务需要重新启动。
- 同一个容器仍有其它在线站点时，下线某个站点会保留其端口映射（避免重启容器），可在容器端口映射中手动删除。
- 两个网关配置指向同一个 Caddy 时，对账会互相删除对方的路由，请一个 Caddy 只配置一个网关。
- Provider File ID 目前只用于图片；Anthropic 官方 Files API 仅经过兼容端点验证。
