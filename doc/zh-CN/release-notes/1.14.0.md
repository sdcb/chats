# Chats 1.14.0 发布说明（TBD）

> 发布状态：TBD（开发中，本文档会随 1.14.0 后续功能持续更新）

Chats 1.14.0 重点改进了模型上下文的一致性、组织级预设模型组、管理员用户控制和多种 Provider 的工具调用兼容性。

## 🧠 用户上下文快照

Chats 现在将界面显示的用户原文与实际发送给模型的上下文分开保存，避免历史消息因为时间、文件或运行环境变化而产生不同的模型输入，并提高 Prompt Cache 前缀保持一致的可能性。

- `StepContentText.Content` 继续保存并展示用户原文；新增的 `ContextTemplate` 保存消息创建时冻结的模型上下文。
- 当前时间、目标模型、Code Interpreter 文件和 Docker session 等动态信息在用户消息创建时写入快照，历史继续对话和重新生成不会重新计算这些信息。
- 同一条用户消息可使用 `{{#spans:1,2}} ... {{/spans}}` 条件块，为不同 span 渲染不同上下文；内容相同的 span 会自动合并和去重。
- 模板统一使用 LF，并在删除不匹配的条件块时一并删除指令行，避免产生额外空行和不稳定的上下文前缀。
- 用户原文在条件解析完成后才替换 `{{USER_CONTENT}}`，其中包含的模板标记、XML 或连续换行不会被再次解释。
- 模板为空时自动回退到 `Content`，旧消息无需回填或迁移。
- 原地编辑消息会保留已有上下文快照；“编辑并发送”创建的新消息会生成新的时间和环境快照。
- 上下文在转换为 Neutral Message 时统一渲染，OpenAI、Anthropic 等 Provider 无需分别实现模板逻辑。

## 🌐 系统预设模型组

- 管理员可以将预设模型组标记为系统预设，使其对所有已登录用户可见。
- 系统预设与个人预设显示在同一列表中，并始终排在个人预设之前；盾牌图标及“系统预设”悬停提示用于区分两者。
- 聊天中的“重设模型”弹窗同样显示系统预设标志。
- 普通用户可以应用和克隆系统预设，但不能编辑、删除或调整其顺序；克隆结果始终是用户自己的个人预设。
- 管理员继续通过原有预设模型组编辑界面维护系统预设；系统预设和个人预设分别排序，不能跨范围移动。
- 应用预设时会重新检查用户拥有的模型和 MCP 权限；权限不足时返回错误，不在列表阶段保存可能过时的预检查结果。
- 本版本继续保留默认 Prompt，后续版本将逐步由系统预设模型组替代相关能力。

## 👤 管理员用户管理

- 用户列表和编辑窗口新增 SSO Sub 与 API Key 权限信息；Account 和登录 Provider 以只读方式显示。
- 管理员可以修改或清空 Keycloak 用户的 Sub；重复的 Sub 会被拒绝。
- 管理员可以直接重置用户密码。新密码必须至少 8 位，并包含大写字母、小写字母、数字和特殊字符中的至少三种。
- 管理员可以禁止用户使用 API Key。关闭权限不会删除已有 Key，但会使其立即失效；重新开启后，未过期且未撤销的 Key 可以恢复使用。
- API Key 权限会同时写入登录 Token claims 和登录响应，前端直接使用登录信息控制入口，不再额外请求权限状态。
- 用户头像菜单中的 API 入口和 Build 页面中的 API Key 页签仅对拥有权限的用户显示，管理员同样遵守该限制。
- API Key 被修改、撤销或删除，以及管理员关闭用户或 API Key 权限时，认证缓存会立即失效，不再存在最长五分钟的延迟。

## 🎁 账号初始配置

- 管理员可以在账号初始配置中预先授予 MCP 权限，并分别设置快捷入口和用户级自定义请求头。
- 初始配置可以决定新用户是否允许使用 API Key；已有配置和已有用户继续保持启用。
- 配置匹配改为确定性规则：同时匹配登录类型和邀请码的配置优先，其次是邀请码、登录类型和无限制配置；同级配置按最近更新时间稳定选择。
- 初始化配置引用的 MCP 后续被删除时，新用户创建会跳过该 MCP 并记录警告，不会阻断注册或影响其他初始资源。

## 🔧 Provider 与工具调用兼容性

- **修复流式工具调用交错导致保存失败**：部分 OpenAI 兼容 Provider 会在工具名称和参数增量之间插入普通文本。Chats 现在按响应中的工具调用 `Index` 跨文本片段归并，避免保存 `Name = NULL` 的工具调用记录。该修复仅调整内存聚合，不增加数据库访问。
- **修复 DeepSeek Messages API 多轮工具调用失败**：发送给 DeepSeek 时会忽略只有 signature、没有思考正文的空 thinking block，避免后续请求因为不支持 `redacted_thinking` 而返回 HTTP 400。包含正文的 thinking 及其 signature 仍会保留，其他 Anthropic Provider 行为不变。
- **修复 Anthropic Messages 并行工具结果分组**：同一个 assistant message 发起多个 `tool_use` 时，对应的 `tool_result` 及附件会合并到紧随其后的同一个 user message，避免兼容接口报告缺少工具结果。

## ⚠️ System Prompt 动态变量弃用计划

- 新安装 Chats 时创建的默认 system prompt 不再包含当前日期；时间和模型信息已迁移到用户上下文快照。
- 1.14.0 仍保留 `{{CURRENT_DATE}}`、`{{CURRENT_TIME}}` 和 `{{MODEL_NAME}}` 的替换逻辑，以兼容已有默认提示词和用户自定义提示词。
- 本版本不会迁移或修改已有 system prompt 数据。
- **Chats 1.15 将彻底删除上述三个动态变量。** 升级到 1.15 前，请从自定义 system prompt 中移除这些变量。

## 🧪 稳定性与测试

- 覆盖上下文模板生成、span 条件渲染、内容去重、换行规范化、非法模板和用户原文隔离。
- 覆盖多个 span 删除条件块后无多余空行、历史消息回退、模板克隆和模型消息内容顺序。
- 新增管理员密码规则与 API Key 登录 claims 单元测试。
- Provider 兼容性修复均增加了对应的回归测试。

## ⬆️ 升级提示

- SQL Server 部署请运行：`src/scripts/db-migration/1.14/1.14.0.sql`
- 迁移将为 `StepContentText` 新增可空的 `ContextTemplate NVARCHAR(MAX)`，为 `ChatPreset` 新增 `IsSystem`，为 `User` 新增 `ApiKeyEnabled`，并为 `UserInitialConfig` 新增 MCP JSON 和 API Key 初始权限字段。
- 历史消息不回填上下文模板；已有预设保持个人预设；已有用户默认允许使用 API Key。
- 已有 system prompt 不会被自动修改。请提前检查并逐步移除 `{{CURRENT_DATE}}`、`{{CURRENT_TIME}}` 和 `{{MODEL_NAME}}`，为 1.15 的正式删除做好准备。
