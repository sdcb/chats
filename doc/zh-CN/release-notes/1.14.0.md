# Chats 1.14.0 发布说明（TBD）

> 发布状态：TBD（开发中，首项功能记录于 2026-08-08，本文档会随 1.14.0 后续功能持续追加）

1.14.0 的第一个功能是一次围绕 **模型上下文稳定性与 Prompt Cache 命中率** 的聊天存储重构。Chats 现在会把用户在界面中看到的原始内容，与实际发送给模型的上下文模板分开保存；当前时间、目标模型和 Code Interpreter 状态不再依赖每次请求临时重建，而是在用户消息创建时冻结，并在发送给不同 span 时按条件渲染。

## 🧠 用户上下文模板重构

### 1) UI 内容与模型上下文分离

- 📝 **原始用户内容保持独立**：`StepContentText.Content` 继续保存用户输入的原文，聊天界面、编辑和复制等功能仍只读取该字段。
- 🧊 **模型上下文冻结**：新增可空字段 `StepContentText.ContextTemplate`，保存该用户消息创建时的模型上下文模板。历史消息重新发送或重新生成回答时直接复用已保存模板，不再按照当前环境重新生成历史时间、文件和 Docker 会话信息。
- 🔙 **历史数据自然兼容**：旧消息的 `ContextTemplate` 保持 `NULL`，发送时自动回退到原始 `Content`，无需回填或重写历史聊天记录。
- ✏️ **编辑行为保持直观**：用户修改消息原文时保留原上下文模板，只替换模板中的用户内容占位符；通过“编辑并发送”创建的新用户消息则生成新的时间与上下文快照。

### 2) 按 Span 条件渲染

- 🎯 **共享用户消息、按 span 渲染**：继续采用“一个共享 UserTurn、多个 Assistant 候选回答”的聊天结构，同一条用户消息可以针对不同 span 生成不同的模型输入。
- 🧩 **轻量条件语法**：上下文模板支持独占行的 `{{#spans:1,2}} ... {{/spans}}` 条件块。发送请求时只保留与目标 span 匹配的内容，再替换 `{{USER_CONTENT}}`。
- ♻️ **自动合并去重**：相同类型且内容完全一致的上下文会自动合并 SpanId，并按升序生成一个条件块，避免多个 span 使用相同模型或相同 Code Interpreter 状态时重复保存大段文本。
- 📐 **空白字符稳定**：模板生成和渲染统一使用 LF；删除不匹配条件块时会同时移除指令行，不留下额外空行，从而保证历史上下文可以逐字符稳定重放。
- 🛡️ **严格模板约束**：条件块禁止嵌套，SpanId 必须为合法 `byte`，用户内容在条件解析完成后才进行单次替换，因此用户原文中的模板标记、XML 和换行不会被二次解释。

### 3) 动态信息迁移到用户上下文

- 🕒 **用户本地时间**：根据请求携带的时区偏移生成 `yyyy-MM-ddTHH:mm:sszzz` 格式的本地时间，并冻结到用户上下文中。
- 🤖 **当前模型**：每个 span 使用的模型名称写入对应条件上下文；多个 span 使用同一模型时自动合并。
- 🐳 **Code Interpreter 状态**：云文件、有效 Docker session 等信息只写入启用了 Code Interpreter 的 span 条件块，并在消息创建时冻结。
- 🚚 **统一 Provider 前转换**：模板在 `Step` 转换为 Neutral Message 时按目标 SpanId 渲染，OpenAI、Anthropic 等具体 Provider 无需分别实现模板处理逻辑。
- 🧹 **移除临时注入链路**：删除原先仅在当前请求前临时 prepend Code Interpreter context 的逻辑，避免上下文重复注入，并让重新生成和历史继续对话使用一致数据。

## ⚠️ System Prompt 动态变量弃用计划

- 新安装 Chats 时创建的默认 system prompt 不再包含当前日期，system prompt 的职责收敛为长期、稳定的模型指令。
- 1.14.0 暂时保留 `{{CURRENT_DATE}}`、`{{CURRENT_TIME}}` 和 `{{MODEL_NAME}}` 的替换逻辑，仅用于兼容已有数据库中的默认提示词和用户自定义提示词；本版本不会迁移或修改这些已有数据。
- **已决定在 Chats 1.15 中彻底删除 system prompt 对上述三个动态变量的支持。** 升级到 1.15 前，仍在自定义 system prompt 中使用这些变量的用户需要自行移除；时间和模型信息将统一由用户上下文模板提供。

## 🧪 测试与稳定性

- 新增上下文模板生成、按 span 渲染、自动去重、换行规范化、非法模板和用户原文隔离测试。
- 增加多个 span 条件块的精确输出测试，确认删除前置 span 块后不会为后续 span 留下多余空行。
- 覆盖模型名称按 span 合并、模板克隆、旧消息回退和模型消息内容顺序。
- 🛠️ **修复流式工具调用交错导致保存失败**：部分 OpenAI 兼容 Provider 会在同一个工具调用的具名片段与参数增量之间插入普通文本。工具调用现在按响应内的 `Index` 跨文本片段归并，不再要求所有参数片段严格相邻，避免生成 `Name = NULL` 的 `StepContentToolCall` 并触发数据库保存异常。该修复完全在内存聚合阶段完成，不增加数据库访问次数。

## ⬆️ 升级提示

- SQL Server 部署运行：`src/scripts/db-migration/1.14/1.14.0.sql`
- 迁移仅为 `StepContentText` 新增可空的 `ContextTemplate NVARCHAR(MAX)` 字段，不回填历史数据。
- 现有 system prompt 不会在 1.14.0 升级过程中被自动修改；请提前检查并逐步移除 `{{CURRENT_DATE}}`、`{{CURRENT_TIME}}` 和 `{{MODEL_NAME}}`，为 1.15 的正式删除做好准备。
