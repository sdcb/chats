# Chats 1.16.0 Release Notes

Chats 1.16.0 improves large branching-chat performance, adds physical deletion for Models and Model Keys, and makes message editing and image input substantially more capable. It also adds themed PNG export for assistant answers and several desktop/mobile interaction improvements.

## Lazy Loading for Branching Chats

- The new `GET /api/chats/{chatId}/messages` view endpoint loads the currently visible message path instead of the entire chat tree on first open.
- Lightweight branch metadata remains available for sibling navigation, while hidden branches do not carry their full Step/Content payload until selected.
- Selecting another branch asynchronously loads its sibling subtree and the default visible descendant path, reducing initial response size and client-side parsing for large chats.

## Physical Deletion for Models and Model Keys

- Administrators can physically delete active `Model` records instead of having deletion silently degrade to disabling a model.
- `ChatConfig.ModelId` is nullable and uses `ON DELETE SET NULL` for `ChatConfig`, `ChatSpan`, and `ChatPresetSpan`, so historical configuration remains readable while deleted models are shown as unavailable.
- Active associations such as `UserModel`, `UserApiModel`, and `UserApiCache` are cleaned up on deletion. Immutable model, key, and chat-config snapshots remain available for historical chats and usage records.
- A Model Key can be deleted when it has no enabled models. Deleting or disabling all models under a key cleans up active associations while preserving historical snapshots and transactions; deletion is rejected while an enabled model still exists.

## Message Editing and Image Input

- User messages now use the full `MessageContentEditor`, allowing text and existing images to be edited together, with image add/remove, device upload, remote-file selection, clipboard paste, and drag-and-drop upload.
- The backend supports rich-content in-place editing and editing into a new message; shared validation, turn construction, and usage calculation are unified.
- Paste/upload events and the `Alt+S` shortcut are scoped to the active input area, so the message editor and bottom `ChatInput` no longer interfere with one another.
- Editing a non-terminal branched response no longer unexpectedly changes the leaf or scrolls to the bottom, and editor state remains stable while messages re-render.

## Assistant Answer PNG Export

- Assistant answers can be exported directly from the action bar as a single PNG long image.
- Export reuses the rendered Markdown, KaTeX, Mermaid, syntax highlighting, tables, images, and tool-result output already shown on the page.
- The image follows the current light/dark theme, adapts resolution to the device pixel ratio, and protects against browser limits for very large answers.

## Interaction and Layout Improvements

- Mobile chat toolbars keep MCP shortcuts, Smart Search, and Agent controls on one compact line without wrapping.
- `IconLoader` now uses a stable inline-flex wrapper for consistent rotation across chat input, uploads, session management, sidebars, message actions, and administration pages.
- Session-list titles no longer clip descenders in letters such as `g`, `j`, `p`, `q`, and `y`.

## 🐛 Bug Fixes

- **Reasoning display**: prevents empty duplicate thinking blocks when Responses API reasoning items contain only signatures without displayable thinking text; real streamed thinking remains visible and historical empty blocks are hidden.
- **Model Key possible models**: fixes `InvalidOperationException` on `/api/admin/model-keys/{modelKeyId}/possible-models`, caused by EF Core being unable to translate `GroupBy` with `StringComparer.Ordinal`. Database filtering now runs first and ordinal grouping occurs in memory.

## Upgrade Notes

- The backend project version is `1.16.0`.
- Existing SQL Server deployments must run `src/scripts/db-migration/1.16/1.16.0.sql`; SQLite deployments must run `src/scripts/db-migration/1.16/1.16.0-sqlite.sql`. These migrations make the model reference nullable and apply the new foreign-key deletion behavior.
- Back up the database before migration, and publish the matching backend and frontend only after the migration completes.
