# Chats 2.0

Release date: TBD

Chats 2.0 turns a chat from "one HTTP request" into a durable, interactive and publishable agent run, as described in the vision issue [#155](https://github.com/sdcb/chats/issues/155).

## Permanent containers, volumes and quotas (#149)

- Docker volumes are really created and removed. Permanent containers mount an internal volume at the work directory and can mount standalone user volumes (optionally read-only).
- Container port mappings: each runtime node has a host port pool (`PortRangeStart`/`PortRangeEnd`) and a public address (`PublicHost`). Changing mounts or port mappings recreates the container.
- Admins bypass user container quotas (node limits still apply). Quotas gain `MaxPortMappings` and `MaxPublishedSites`.
- The chat input lets you choose which permanent containers the chat may use.
- Disabling a user stops their containers; cleaning up a container also releases its port mappings and internal volume.

## Resumable chat runs (#150)

- Every generation is a persisted run (`ChatRun`/`ChatRunEvent`). It keeps running when the client disconnects or refreshes; events carry an SSE `id:` and can be resumed via `GET /api/chat-runs/{runId}/events?after=N`.
- Opening a chat reattaches to its active run. Stop is recorded by run id in the database, so it works across instances.
- Orphaned runs (no heartbeat for 60 seconds) are marked failed. Events of finished runs are deleted after `ChatRun:EventRetentionMinutes` (default 60).
- The SSE stream sends keep-alive comments during long silent tool calls so proxies don't drop it.

## Plan mode and ask_question (#151)

- A "Plan" mode in the chat input (remembered per chat) makes the model plan before acting.
- Built-in `ask_question` tool (1–3 questions; single choice, multiple choice or text, with defaults). The run suspends without holding a thread; answering, skipping or sending a new message continues the same reply. History shows answered question cards.

## Mid-run steering (#152)

- While a run is in progress the input becomes "Add to run": messages queue and are injected after the next tool result, or trigger one extra round when no tool call follows.
- Messages not injected when the run stops or ends are discarded and put back into the input. The queue survives a page refresh.

## Website hosting (#153)

- Publish a permanent container port as `https://<sub>.<domain>`: port mapping → DNS conflict check → DNS records → route via the Caddy2 Admin API. Any failure rolls back in reverse order, and each step is logged as an event.
- DNS providers: Cloudflare and Aliyun DNS. Only records marked as created by Chats are managed; other records are never overwritten. Supports A/AAAA (gateway public IP) or CNAME (DDNS host name) and a configurable public port.
- Gateway and DNS credentials are stored AES-GCM encrypted with a key derived from `ENCRYPTION_PASSWORD` and are never returned by the API. **Set `ENCRYPTION_PASSWORD` and keep it safe; changing it requires re-entering the credentials.**
- A reconcile service re-applies routes, removes orphaned routes and unpublishes sites whose container is gone.
- AI tools `publish_website` / `list_websites` / `unpublish_website`, offered only when the chat can see a running permanent container.
- Admin page `/admin/websites` (sites, domains, gateways, DNS providers) and a "Websites" tab in user settings with one-click unpublish.

## Provider file id reuse (#154)

- Images are uploaded once to the provider Files API and then referenced by `file_id` instead of resending base64: OpenAI/Azure/DeepSeek Responses, DeepSeek Chat Completions, Anthropic/DeepSeek Messages.
- Expiry pre-check; when the provider reports an invalid file id the mapping is invalidated and the file re-uploaded once, then inline content is used. Unsupported endpoints back off automatically.
- Remote files are cleaned up when the file or model key is deleted. Configuration section `ProviderFiles` (`Enabled`, `DisabledModelKeyIds`, `DisabledProviderIds`, `OpenAIExpiresAfterSeconds`, …).

## Upgrade notes

- Database migration: SQL Server runs `src/scripts/db-migration/2.x/2.0.sql`, SQLite runs `src/scripts/db-migration/2.x/2.0-sqlite.sql`.
- For website hosting, Caddy must expose its Admin API. Run it from JSON config with `--resume` so reloading a Caddyfile doesn't drop routes added by Chats. TLS certificates are handled by Caddy.
- OpenAI-compatible endpoints such as `/v1/chat/completions` don't use runs, ask_question or steering.

## Known limitations

- Publishing a new port recreates the container: processes stop and only data in mounted volumes is kept, so services must be started again.
- When other live sites still use a container, unpublishing one site keeps its port mapping (to avoid restarting the container); remove it manually from the container's port mappings if needed.
- Two gateways pointing to the same Caddy delete each other's routes during reconcile; configure one gateway per Caddy.
- Provider file ids are used for images only; Anthropic's official Files API has only been verified through compatible endpoints.
