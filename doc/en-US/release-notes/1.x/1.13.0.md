# Chats 1.13.0 Release Notes

> Release Date: 2026-08-05 (23 non-merge commits since 1.12.0.702)

Chats 1.13.0 focuses on improving the **MCP experience** and **provider-native web search**. Users can now pin frequently used MCP servers as shortcut buttons in the chat input, while MCP Server Instructions can automatically extend the model context. Smart Search now covers OpenAI/Azure Responses, DeepSeek Messages, Xiaomi MiMo, and related protocol variants, with better presentation and round-tripping of search activity, citations, and multi-turn history. This release also fixes reasoning-content ordering and clipboard operations on LAN HTTP deployments, and upgrades the project to Node.js 24, MCP SDK 2.0, and newer frontend and backend dependencies.

## 🎯 Core Features

### 1) MCP Shortcut Buttons

- ⚡ **Chat input shortcuts**: assigned MCP servers can be displayed as dedicated buttons in the chat input, letting users enable or disable an MCP for every tool-capable model in the current chat without repeatedly opening chat settings.
- 👤 **Per-user shortcut preference**: `Show Shortcut` is stored on the user-to-MCP assignment, so each user can independently choose whether the same MCP appears as a shortcut.
- 🧑‍💼 **Centralized assignment management**: admins and MCP owners can update shortcut settings for assigned users. Admins can also specify the setting while assigning a new user, with new assignments defaulting to the assigner's current shortcut preference.
- 🧭 **Shown only when applicable**: shortcut buttons remain hidden when no MCP shortcuts are configured or when the current chat has no model capable of tool calls.

### 2) MCP Server Instructions

- 📝 **Fetch server instructions**: refreshing an MCP tool list now also reads `ServerInstructions` exposed by the MCP SDK and automatically fills the MCP editor.
- ✏️ **Review and edit before saving**: server instructions can be adjusted before saving and remain optional for MCP servers that do not provide them.
- 🧠 **Automatic model-context injection**: at chat runtime, instructions from enabled MCP servers are ordered by MCP label and appended to the system message while preserving the existing system prompt and Code Interpreter instructions.
- 🔄 **MCP SDK 2.0**: upgrades `ModelContextProtocol.Core` to 2.0.0 and improves asynchronous disposal and error handling for MCP clients and HTTP transports.

## 🌐 Smart Search & Protocol Support

### 1) OpenAI / Azure Responses Web Search

- 🔍 **Native `web_search` tool**: OpenAI and Azure AI Foundry models using the Responses API can enable hosted web search from the Smart Search button in the chat input.
- 🔗 **Search activity and citation presentation**: parses `web_search_call`, search status, and `url_citation` data, presents search activity and sources through the unified tool-call UI, and preserves them in chat history.
- 🧩 **Complex response compatibility**: extracts citations from nested objects and arrays, fixes incorrect call/result pairing when multiple searches are interleaved, and preserves the search presentation after history is reloaded.
- 🔌 **Endpoint compatibility**: Responses and Models requests recognize endpoints that already include `/v1` or the target resource path, avoiding duplicated URL segments. Streaming, background responses, polling, and cancellation are handled consistently.
- 🚦 **More accurate error classification**: Responses failures distinguish content-safety blocks from ordinary upstream errors and prefer the detailed error message returned by the provider.

### 2) DeepSeek and MiMo Web Search

- 🐋 **DeepSeek Messages hosted search**: DeepSeek's Anthropic Messages-compatible endpoint supports the `web_search_20250305` server tool, including streamed search calls, results, and citations.
- 🧾 **History can continue the conversation**: native DeepSeek `server_tool_use` and `web_search_tool_result` blocks are retained internally and reconstructed for later upstream requests. The frontend converts them into the unified search card and omits encrypted content that should not be exposed.
- 📱 **Xiaomi MiMo search support**: MiMo Chat Completions adds the `web_search` tool according to chat configuration and converts response annotations into results containing titles, URLs, summaries, sites, publish times, and related metadata.
- 🎛️ **Unified Smart Search toggle**: when a chat contains web-search-capable models, the input displays a Smart Search button that updates every capable chat span together.

## 🛠️ Protocol & Stability Improvements

- 🧠 **Reasoning order fix**: when a Chat Completions delta or response contains both reasoning and visible content, reasoning is always persisted and presented first, preventing earlier reasoning from appearing after the final answer.
- 🔀 **Reasoning field compatibility**: recognizes both `reasoning_content` and `reasoning` from upstream providers, and consolidates reasoning round-tripping and history serialization for MiniMax, MiMo, and related models.
- 🌊 **Responses dialect compatibility**: handles direct `reasoning_text`, terminal events, usage data, and output structures used by DeepSeek, MiMo, and other Responses-compatible services. A stream that ends without a terminal event is now reported as an upstream failure instead of an apparently successful partial response.
- 📚 **Stable historical content ordering**: restores step contents from the database in content-ID order, reducing ordering errors among tool calls, reasoning, and visible text in subsequent requests.
- 📋 **Clipboard fix for LAN HTTP deployments**: introduces a shared copy helper with a compatibility fallback when the Clipboard API is unavailable in a non-secure context. Code blocks, messages, Mermaid, Request Trace, session commands, and configuration pages now use the same behavior.
- 🌍 **Resource-domain fix**: updates download links, build documentation, model icons, and related resources after the previous `sdcb.pub` domain became unavailable.

## ⚙️ Engineering & Operations

- ⬆️ Upgrades the frontend build environment to Node.js 24.18.0 and npm 12.0.1, with Node.js 24 and npm 12 declared as the minimum supported versions.
- 📦 Updates Next.js, React, Entity Framework Core, Azure/AWS SDKs, Playwright, Swashbuckle, MiniExcel, and other frontend and backend dependencies, including npm security-audit fixes.
- 🗃️ Adds an explicit native SQLite runtime dependency and provides both SQL Server and SQLite migration scripts for 1.13.0.
- ☁️ Expands the Azure Blob-to-MinIO migration utility with safe-by-default dry runs, source probing, MinIO sampling, parallel migration, item limits, missing-source handling, optional source deletion, and progress statistics.
- 🚀 Updates the release pipeline to upload frontend and backend source artifacts to R2 under `release/latest`, and updates the self-hosted deployment runner labels.

## 🐛 Fixes

- Fixes Responses web-search citations that are nested in array fields not being recognized.
- Fixes citations being attached to the wrong search when multiple Responses web-search calls are interleaved.
- Fixes hosted search being shown as a generic tool call, or losing its result presentation, after messages are refreshed or reloaded.
- Fixes Chat Completions reasoning segments appearing after visible answer content.
- Fixes copy buttons failing when Chats is accessed over a LAN HTTP address.
- Improves handling of timeout, JSON, IO, and invalid-response failures while fetching MCP tools.
- Fixes dynamic component caching potentially reading a stale component during React rendering, and adjusts the frontend ESLint configuration for the upgraded rule structure.

## ⬆️ Upgrade Notes

- For SQL Server deployments, run: `src/scripts/db-migration/1.13/1.13.0.sql`
- For SQLite deployments, run: `src/scripts/db-migration/1.13/1.13.0-sqlite.sql`
- The database migration includes:
  - A nullable `McpServer.ServerInstructions` field for storing MCP server instructions.
  - A non-nullable `UserMcp.ShowShortcut` field. Existing assignments are initialized to `false`, so upgrading does not automatically expose existing MCP servers in the chat input.
- If you build the frontend yourself, upgrade the environment to Node.js 24 and npm 12. The repository's Volta configuration uses Node.js 24.18.0 and npm 12.0.1.
- The `fetch-tools` response changes from a tool array to an object containing `tools` and `serverInstructions`. External management tools that call this endpoint directly must update their response handling.
