# Chats 1.17.0

Release date: 2026-08-27

This release completes the current model-configuration, image-generation, branching-chat, and user-management work.

## Response speed statistics

- Token speed now measures only the generation phase after the first token (TTFT). TTFT is subtracted from total elapsed time so provider startup latency no longer makes generation speed appear artificially slow.
- Output-token counting keeps its existing definition. When no valid generation interval remains after subtracting TTFT, the UI displays `-` instead of infinity or a negative value.

## Image-generation background mode

- Image-generation models, ChatConfig, configuration snapshots, chat-config APIs, and preset configuration now support background mode: default (`NULL`, omitted from the request), `auto`, `opaque`, and `transparent`.
- The configuration UI shows “Default” initially. Choosing a custom value exposes `auto`, `opaque`, and `transparent`; selecting a transparent background while using JPEG shows a Toast explaining the format conflict.
- SQL Server and SQLite migrations add the setting and include it in configuration snapshots and hash calculations. The default remains the provider API’s default behavior.

## Model context prompts

- Image-generation models now use the user’s original text directly as the prompt instead of wrapping it in `UserContextTemplate`.
- Text and Agent models retain the current time and other required runtime context in their context templates, without injecting the model name a second time.

## Stable branching-chat pagination

- Fixed a live SSE issue where the final message could omit `siblingIds`. Regeneration and failed generations no longer leave the frontend unable to locate the current branch, display `0/N`, or request `undefined/subtree`.
- When sending user and final assistant messages, the backend now fills in sibling-branch metadata from the current chat turn so live responses match refreshed message queries.

## User management and password changes

- Separate forms for creating users, editing users, and changing passwords prevent hidden password fields from remaining in the edit form and blocking saves without an error.
- Fixed the password-change form not submitting when validation state was out of sync with the latest input.
- The password dialog displays the target user’s actual login account as read-only and supplies `autocomplete` hints so browser password managers associate the new password with the correct account.
- New-password and confirmation fields support click-to-reveal plain text.

## OpenAI image endpoints and model-configuration stability

- Fixed image-generation and image-edit requests that duplicated `/v1` when a Model Key or model-level URL already contained that path, producing requests such as `/v1/v1/images/...`.
- Image generation and editing now recognize existing `/v1` segments while preserving the model-level Custom URL precedence.
- Added a single entry-point validation for nullable `ChatConfig.Model`, returning a clear internal-configuration error instead of allowing a null-reference failure during execution.
- Removed nullable compiler warnings from the backend web, model-service, and test projects and added a regression test for missing model configuration.

## Upgrade notes

- This release includes the 1.17.0 SQL Server and SQLite migrations for image-generation background mode. Apply the migration that matches your database before using the new setting.
- No migrations are introduced for the other fixes and UI improvements in this release.
