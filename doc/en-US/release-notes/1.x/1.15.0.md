# Chats 1.15.0 Release Notes

Chats 1.15.0 removes compatibility behavior retained from 1.14.0 and converges Prompts into named, searchable plain-text shortcuts.

## MCP Server and Tool Metadata

- MCP Server protocol `Name` is now separate from user-facing `DisplayName`. `Name` must match `^[A-Za-z0-9_-]{1,50}$` and is used to build stable model-side tool names, `mcp__<server.Name>__<toolName>`. Model-facing instructions use `DisplayName (Name)` when a display name exists; management pages and shortcut pickers show the display name or protocol name according to context.
- Tool management supports editing `Title`, `Description`, and `Parameters`, with compact switches for `ReadOnly` and `Idempotent`. Refreshing tools still replaces the complete tool table and synchronizes four MCP annotation hints; undeclared values are stored as `false`. `Destructive` and `OpenWorld` are retained as backend metadata only in this release.
- Tool-call records store a display-name snapshot. History and untitled-tool fallbacks use the protocol name; SSE, live tool cards, and historical messages retain the original protocol name for model interaction, copying, and identification.

## Parallel MCP Calls and Retries

- Consecutive `ReadOnly=true` MCP calls form parallel batches with at most four concurrent calls. Non-read-only tools, Code Interpreter, and unknown tools remain serial barriers, and batches execute in strict model-call order.
- Failed `Idempotent=true` calls retry at most twice (three total attempts), with approximately 1- and 2-second backoff plus small jitter. A client is lazily created and reused per MCP Server within one model-output step; tool-error retries reuse healthy clients, while connection or session failures evict and rebuild the client on demand without an extra `ListToolsAsync` call.
- `Destructive` and `OpenWorld` are stored and synchronized as editable metadata only; they do not change confirmation or execution policy yet. Final tool failures are returned to the model and do not abort the whole chat.

## MCP Configuration Validation

- A chat configuration cannot enable MCP Servers with the same name (case-insensitive), even when they belong to different owners. The shortcut picker, presets, shortcut buttons, and server-side saves all validate this rule.
- Renaming a Server `Name` is rejected when it would create a duplicate within a chat or preset that already uses the Server.

## Prompt Behavior Convergence

- Prompt tables, personal/system/default Prompts, the management UI, CRUD APIs, temperature settings, and `/xxx` shortcut selection remain available.
- Selecting a Prompt inserts its content verbatim into the chat input or System Prompt.
- `{{CURRENT_DATE}}`, `{{CURRENT_TIME}}`, and `{{MODEL_NAME}}` are no longer replaced automatically.
- Custom placeholders such as `{{name}}` no longer open a variable-entry dialog or perform substitution.
- Existing `{{...}}` content requires no migration and continues to be stored and sent as ordinary text.

## Retry Configuration Convergence

- The compatibility setting `Chat:Retry429Times` has been removed; the .NET configuration system silently ignores the old setting in 1.15.
- Deployments use `Chat:MaxTransientRetries`, defaulting to `5`; setting it to `0` disables retries.
- Retries still occur only before the first output segment and cover 408, 429, 500, 502, 503, 504, and transient network/internal timeout errors.

## MCP User Assignment UX

- The assigned-user area is now a compact four-column table: User, Headers, Shortcuts, and Actions. Long usernames stay on one line and are ellipsized, with the full value available on hover.
- Custom-header editors use a shorter single-line height while retaining multiline JSON input, scrolling, validation, and saving. The Shortcuts column is narrowed to free more horizontal space for headers.
- Removing a user immediately returns that user to the available list. Reassigning the user before saving restores its unsaved headers and shortcut settings.

## Chat Tool-Call UX

- `ToolCallBlock` no longer lets later messages or display order take over expansion state. Parallel tools can display independently without being collapsed by a new tool call.
- A tool stays expanded from streamed argument generation through progress output, then collapses one second after completion. GPT Responses web search collapses promptly when `web_search_call` completes; later citations/results update the card without reopening it.
- Automatic expansion/collapse supports `Chatting`, `Reasoning`, and `Pending` live states. Fast tools without progress briefly show their final result; historical tools start collapsed, and manual expansion/collapse is not overridden by automation.

## 🐛 Bug Fixes

- **Responses reasoning signature round-trip**: fixes OpenAI/Azure AI Foundry Responses requests in tool-heavy flows where complete `encrypted_content` from consecutive reasoning output items was concatenated as ordinary thinking text, causing `invalid_encrypted_content` on the next request. Completed reasoning signatures now remain separate items, while streamed thinking text within the same item still merges with its final signature. Rebuilt historical requests preserve the original reasoning, web-search, function-call, and assistant-message order.
- **GPT web-tool collapse**: separates hosted web-search execution completion from result-display readiness, so `search`, `open_page`, and `find_in_page` no longer remain expanded while the entire streamed answer waits for body citations.
- **MCP preset idempotency**: prevents repeated application of the same preset from inserting duplicate `ChatConfigMcp` links, and removes stale database links when an empty MCP preset is applied. Preset application now fully synchronizes MCP links while preserving custom headers and consolidating historical duplicates; request assembly also deduplicates Servers so dirty data cannot inject instructions and tool definitions repeatedly. No database migration is required for this fix.
- **Markdown math parsing**: disables single-dollar math syntax to prevent amounts, URLs, and shell variables from being misread as formulas and swallowed across blocks by KaTeX. `$$...$$` remains supported, along with the common `\(...\)` and `\[...\]` delimiters.
- **LaTeX compatibility normalization**: normalizes delimiters at the shared Markdown rendering entry point without modifying the original message, skips inline code and fenced code blocks, and preserves unfinished streaming content. Fenced code with trailing text is no longer mistaken for a closing fence.
- **Streaming Markdown**: moves the `▍` cursor out of Markdown/KaTeX source and inserts it during the rehype phase after the last visible node and before trailing newlines, avoiding Unicode warnings during formula generation and preventing the cursor from dropping to the next line.
- **Markdown layout**: improves top spacing when a main heading immediately follows body text.
- **Mobile user management**: moves password changes into a separate security action, shortens the edit form, constrains the user dialog to the mobile viewport, and keeps the bottom save button visible.

## Dependencies and Security Maintenance

- .NET and Entity Framework Core dependencies upgrade from `10.0.9` to `10.0.11`; the Npgsql Entity Framework Core provider upgrades from `10.0.2` to `10.0.3`.
- Microsoft Playwright upgrades from `1.61.0` to `1.62.0`, AWS SDK for S3 from `4.0.100.3` to `4.0.102.1`, and Microsoft.NET.Test.Sdk from `18.7.0` to `18.9.0`.
- Removes the redundant explicit `SQLitePCLRaw.lib.e_sqlite3` reference; Entity Framework Core's SQLite bundle now manages it transitively. The bundled native SQLite engine remains `3.53.3`.
- A NuGet vulnerability audit including transitive dependencies found no known-vulnerable dependencies after these upgrades.

## Upgrade Notes

- The backend project version is now `1.15.0`.
- New Responses reasoning signatures are stored with their original item boundaries. Encrypted content already corrupted by concatenation in older historical conversations cannot be recovered automatically; if `invalid_encrypted_content` persists, retry from before the affected turn or start a new chat.
- Change the environment variable from `Chat__Retry429Times` to `Chat__MaxTransientRetries`, or change the command-line option to `--Chat:MaxTransientRetries`.
- For SQL Server, run `src/scripts/db-migration/1.15/1.15.0.sql` first; for SQLite, run `1.15.0-sqlite.sql`. The migration preserves historical MCP `Label` values as nullable `DisplayName`, backfills protocol `Name` from `<McpServer.Id>`, and sets historical values of all four tool hints to `false`.
- Publish the matching backend and frontend only after the database migration completes. 1.15 is incompatible with the old MCP `label` API field.
